## Categories

The [service catalog](/services/) groups services by user goal, in this order: {new Intl.ListFormat('en', { type: 'conjunction' }).format(serviceCatalogGroups.map((group) => group.title))}. The table above follows the same order. Implementation boundaries differ inside every category. Some are external emulator processes, some are local facades, and some require Docker-socket or transparent-network opt-ins.

## How to use the catalog

- Load the actual running endpoints with `localcloud env`; the host CLI may remap ports.
- Check the service detail and operation limitations before relying on a workflow.
- Keep the runtime listening only on localhost and use fake local data.
- Remove emulator variables and validate production behavior against real Google Cloud before release.

Open the [service catalog](/services/) for all {publishedServiceCount} guides or [Compatibility](/compatibility/) for operation-level support and limitations.
