# BigQuery emulator feature reference

LocalCloud packages an advanced, production-grade local BigQuery engine. The architecture combines the official **GoogleSQL Analyzer (pinned ZetaSQL 2026.9.2)** for exact semantic resolution with **DuckDB 1.5.5 vectorized columnar OLAP execution**.

By default, BigQuery runs as a native in-container process managed by Supervisord inside LocalCloud, requiring **no Docker daemon** on the host.

<Callout type="note" title="Zero silent wrong results (fail-closed)">
Tested against the authoritative GoogleSQL Reference Evaluator across an 88-query edge-case hazard benchmark, the GoogleSQL + DuckDB engine produced **0 silent wrong results**. Unsupported or unlowered syntax fails closed with an explicit error rather than silently returning incorrect data or integer wraps.
</Callout>

## Connection and endpoints

| Surface | Endpoint | Boundary & details |
| --- | --- | --- |
| **REST API** | `http://localhost:5388` | Core BigQuery v2 REST query, table, dataset, and job lifecycle APIs. |
| **Storage API (gRPC)** | `localhost:5389` | High-throughput Storage Read (Arrow IPC & AVRO) and Storage Write API. **TLS is always required** on this listener. |
| **SDK environment** | `BIGQUERY_EMULATOR_HOST=http://localhost:5388` | Standard emulator variable recognized by official Google Cloud SDKs. |
| **Gateway proxy** | `http://localhost:5380/bigquery/v2/` | Optional gateway access subject to edge IAM policy evaluation. |
| **Execution mode** | Native in-container (Supervisord) | Native Linux process; Docker daemon is required only if an optional custom companion image is configured. |
| **Persistence** | Mounted volume `/var/lib/localcloud/bigquery-data` | DuckDB database files and JSON metadata survive container restarts when a persistent data volume is mounted. |

## Feature categories

LocalCloud organizes BigQuery's capabilities into logical, production-grade functional areas:

### 1. Machine Learning & Predictive Analytics (BQML)
- **Model Training**: Create and train machine learning models directly in SQL using `CREATE MODEL` with tabular algorithms (linear regression, logistic regression, k-means, matrix factorization).
- **Inference & Evaluation**: Full support for `ML.PREDICT`, `ML.EVALUATE`, and `ML.WEIGHTS` composed with standard queries, CTEs, and write destinations.
- **Preprocessing**: Feature transformation pipelines using `TRANSFORM` clauses embedded in model definitions.

### 2. Generative AI & Embeddings
- **Local LLM Text Generation**: Invoke `ML.GENERATE_TEXT` directly within SQL queries connected to local OpenAI-compatible endpoints (such as Ollama, llama.cpp, or vLLM).
- **Text & Multimodal Embeddings**: Generate vector embeddings in batch or stream via `ML.GENERATE_EMBEDDING` for semantic search and retrieval pipelines without external API costs.

### 3. Vector Search & Full-Text Search
- **Vector Indexes**: Create and manage vector indexes with `CREATE VECTOR INDEX`, `DROP VECTOR INDEX`, and `ALTER VECTOR INDEX REBUILD`.
- **Vector Search Execution**: Fast semantic retrieval with `VECTOR_SEARCH` supporting Cosine, Euclidean, and Dot-Product distance metrics.
- **Search Indexes & Scoring**: Full-text indexing with `CREATE SEARCH INDEX`, tokenization, exact `SEARCH` queries, and statistical relevance functions (`TF_IDF`, `BAG_OF_WORDS`).

### 4. Geospatial Analytics & GIS (S2 Spherical Geometry)
- **Spherical S2 Calculations**: Complete native geography functions executed with spherical accuracy: `ST_BOUNDINGBOX`, `ST_INTERSECTSBOX`, `ST_LINEINTERPOLATEPOINT`, `ST_LINELOCATEPOINT`, `ST_LINESUBSTRING`, `ST_MAXDISTANCE`, `ST_CLOSESTPOINT`, `ST_CENTROID_AGG`, and `ST_EXTENT`.
- **Spatial Clustering & GeoJSON**: Spherical DBSCAN clustering per window partition (`ST_CLUSTERDBSCAN`), and native GeoJSON export (`ST_ASGEOJSON`) for points, linestrings, polygons, and multi-part geometries.

### 5. Property Graph Queries (GoogleSQL GQL)
- **Graph Schema Declarations**: Define labeled property graphs directly in BigQuery DDL using `CREATE PROPERTY GRAPH` over node and edge tables.
- **Pattern Matching (`GRAPH_TABLE`)**: Query complex entity relationships, cyclic traversals, and path patterns using the GoogleSQL `GRAPH_TABLE` operator.

### 6. Enterprise Security, Privacy & Data Governance
- **Row-Level Security (RLS)**: Enforced across all query and extraction surfaces (interactive queries, views, Storage Read API, tabledata export, copy jobs, and DML). Managed via row-access policy DDL.
- **Dynamic Data Masking**: Column-level policy tags, predefined masking routines (SHA256, email masks, null masks), and custom masking routines backed by Data Policy API v1.
- **IAM Conditions**: Policy version 3 conditional role bindings evaluated by Google's CEL runtime (`cel-expr-python`) on table and dataset permissions.
- **Differential Privacy**: Privacy-preserving analytics using `WITH DIFFERENTIAL_PRIVACY` (`COUNT`, `SUM`, `AVG`, `PERCENTILE_CONT`).

### 7. GoogleSQL Dialect & Columnar Execution
- **ZetaSQL Semantic Resolution**: Pinned GoogleSQL Analyzer 2026.9.2 provides authoritative type checking, resolution, and name binding.
- **Columnar Engine**: DuckDB 1.5.5 executes analytical scans, joins, aggregations, and window functions 10–100x faster than row-oriented emulators.
- **Rich Data Types**: Full fidelity for 76-digit `BIGNUMERIC`, `NUMERIC(38,9)`, `GEOGRAPHY`, `JSON`, `STRUCT`, and native `ARRAY` operations.
- **Advanced Query Features**: Recursive CTEs, value tables (`SELECT AS STRUCT` / `AS VALUE`), dynamic window parameters (`@offset` parameter bindings), persistent Table-Valued Functions (TVFs with `RETURNS TABLE`), time travel (`FOR SYSTEM_TIME AS OF`), and Table Clones/Copies.

### 8. High-Throughput Ingestion & Database Federation
- **Cloud Storage External Tables**: Vectorized reading of CSV, JSONL, Parquet, Avro, and ORC files directly from emulated Cloud Storage (`gs://`), with schema autodetect and Hive partitioning.
- **Storage Read/Write API**: High-throughput gRPC streaming on port `5389` delivering Arrow IPC and AVRO streams for Apache Spark, Dataproc, and data pipelines.
- **Database Federation (`EXTERNAL_QUERY`)**: Direct live federated queries against PostgreSQL and MySQL databases via bundled DuckDB database extensions.

### 9. Procedural Scripting, Procedures & Sessions
- **Control Flow**: Multi-statement scripting with `DECLARE`, `SET`, `IF`, `WHILE`, `LOOP`, `REPEAT`, `FOR...IN`, and `BEGIN...EXCEPTION` blocks.
- **Dynamic SQL & Stored Procedures**: Dynamic statement execution with `EXECUTE IMMEDIATE (USING / INTO)` and callable stored procedures (`CREATE PROCEDURE` / `CALL`).
- **Sessions & Temp Objects**: Isolated multi-statement user sessions (`createSession`, `BQ.ABORT_SESSION`) with temporary tables and temporary functions.

### 10. Operational Metadata (`INFORMATION_SCHEMA`)
- Full metadata catalog views for `SCHEMATA`, `TABLES`, `VIEWS`, `COLUMNS`, `COLUMN_FIELD_PATHS`, `ROUTINES`, `PARAMETERS`, `TABLE_OPTIONS`, `TABLE_STORAGE`, `OBJECT_PRIVILEGES`, `MATERIALIZED_VIEWS`, `JOBS_BY_USER`, `JOBS_BY_PROJECT`, `JOBS_TIMELINE`, and `SESSIONS_BY_*`.
- Query dry runs with precise byte estimates and `maximumBytesBilled` budget enforcement.

## Production boundary

While LocalCloud provides near-complete local functional parity for development and CI testing, certain infrastructure-scale capabilities remain exclusive to Google Cloud production:
- Distributed Borg reservations, multi-tenant slot allocation, and physical BI Engine memory tiers.
- Cross-region multi-continent dataset replication and geo-distributed disaster recovery.
- Cloud Billing charges, physical multi-tenant quotas, and live Google Cloud Audit Logs.
