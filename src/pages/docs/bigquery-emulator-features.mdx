# BigQuery emulator feature reference

The current LocalCloud source packages a native **GoogleSQL Analyzer** and **DuckDB** query engine. Supervisord manages the BigQuery process inside the LocalCloud Docker container. Running LocalCloud requires Docker; the default BigQuery process does not need a Docker-socket mount. An optional custom BigQuery image uses a companion container and requires Docker access.

<Callout type="warning" title="Source evidence and release qualification">
The operation table describes the current source contract. The mutable LocalCloud image tag has no qualified assembled-image digest in this snapshot. Test the exact image and client you use; source-level implementation and a finite query benchmark do not establish complete semantic parity.
</Callout>

## Connection and endpoints

| Surface | Canonical endpoint | Boundary |
| --- | --- | --- |
| REST API | `http://localhost:5388` | BigQuery dataset, table, job, and query routes. |
| Storage API | `localhost:5389` | Separate gRPC listener with TLS; configure the Storage client and trust the LocalCloud CA. |
| Environment export | `BIGQUERY_EMULATOR_HOST=http://localhost:5388` | Use the actual value from `localcloud env`; some SDKs need explicit client options. |
| Gateway proxy | `http://localhost:5380/bigquery/v2/` | Gateway authentication and routing differ from direct listeners. |
| Persistence | `/var/lib/localcloud/bigquery-data` | DuckDB and metadata beneath the mounted LocalCloud data volume. |

The CLI may remap host ports. The [Python SDK example](/docs/sdk-examples/#bigquery-deterministic-query) passes the generated REST endpoint explicitly and uses anonymous credentials. A REST client configuration does not configure the Storage API client.

## Feature areas to qualify

- **GoogleSQL execution:** test the exact types, expressions, joins, scripting, and error behavior used by the application.
- **BQML:** selected local models are implemented; model types, feature shapes, and `TRANSFORM` variants have documented gaps.
- **Vector Search and text search:** check the specific index, function, and option against the feature inventory.
- **Geography:** spherical functions have bounded geometry and input support, including remaining snapping, covering, and union gaps.
- **Security and governance:** row policies, masking, and IAM-shaped APIs require path-specific tests. Nested policy tags and taxonomy operations have recorded boundaries.
- **External tables and federation:** validate the exact source format and connector. An emulator fixture or stored connection does not prove a live federated query.
- **Storage API and Spark:** qualify transport, TLS, schema, read/write method, connector version, and architecture separately.

The [coverage and known boundaries](/docs/bigquery-coverage-gaps/) page publishes the dependency's recorded matrix counts and the capabilities implemented with documented limits. The [comparison guide](/docs/bigquery-feature-comparison/) explains how to compare local engines without treating benchmark samples as global correctness guarantees.
