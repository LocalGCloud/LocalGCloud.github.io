# Performance and benchmarks

This report records the empirical performance characteristics, throughput limits, and operational latencies of LocalCloud measured using native CLI (`localcloud 0.1.14`) and container image `agentcloud/localcloud:lite`.

<Callout type="note" title="Local Testing and CI Focus">
These benchmarks measure execution on local workstations and CI runners. LocalCloud emulates Google Cloud APIs for developer speed and agentic iteration; validate production scale and quotas against live Google Cloud before deployment.
</Callout>

## Executive summary and readiness matrix

LocalCloud is engineered for high-frequency test suites and autonomous AI coding agents where low overhead directly translates to faster iteration:

- **Rapid AI tool calling**: The MCP stdio bridge executes tool calls (`localcloud_runtime_status`) in **`1 ms`** (&lt; 1 ms, **`1,531 calls/sec`**), eliminating tool overhead for coding agents.
- **Fast in-memory store**: Memorystore (Redis) delivers **`1 ms`** (&lt; 1 ms) GET and SET operations at **`~1,950 ops/sec`**.
- **Low-latency database operations**: Cloud SQL (PostgreSQL) processes point INSERTs in **`2 ms`** (**`656 inserts/sec`**) and point SELECTs in **`2 ms`** (**`416 queries/sec`**). Batch inserts achieve **`>39,000 rows/sec`**.
- **High-speed object storage**: Cloud Storage retrieval completes in **`2 ms`** (**`527 reads/sec`**), and writes in **`5 ms`** (**`209 writes/sec`**).
- **High-throughput messaging**: Cloud Pub/Sub processes single messages in **`3 ms`** and delivers batch ingestion at **`>10,000 messages/sec`**.
- **Zero-to-ready in 5 seconds**: Cold start provisions PostgreSQL migrations and 22 active local Google Cloud emulators in **`~5 s`**; warm start reconciles in **`~333 ms`**.

## Test environment and methodology

- **CLI executable**: Native PyInstaller one-folder bundle `dist/localcloud` (`localcloud 0.1.14`).
- **Container engine**: Docker 29.8.1 on Colima 0.10.3 (VZ backend, Rosetta translation enabled).
- **Runtime image**: `agentcloud/localcloud:lite` (Go Engine `0.1.11`).
- **Data volume**: Dedicated Docker volume `localcloud-perf` mounted at `/var/lib/localcloud`.
- **Project scope**: `local-gcp-project` with caller `local-developer`.
- **Active services (22 enabled)**: `gcs`, `pubsub`, `bigquery`, `cloudsql`, `spanner`, `bigtable`, `memorystore`, `secretmanager`, `cloudtasks`, `cloudscheduler`, `cloudfunctions`, `alloydb`, `dataproc`, `cloudiam`, `cloudresourcemanager`, `serviceusage`, `cloudbilling`, `logging`, `monitoring`, `sheets`, `workflows`, and `kms`.

## Architectural implications

### High-frequency AI coding agent loops

Cloud sandboxes and remote emulation environments introduce 100–500 ms of latency per tool call. LocalCloud's native stdio MCP bridge executes tool calls in **`1 ms`** (&lt; 1 ms). An agent executing 50 intermediate inspection steps spends only **`~33 ms`** in tool overhead, avoiding timeouts and context pauses.

### Fast local test suites

Integration test suites (`pytest`, `go test`, `vitest`) create, inspect, and tear down cloud resources rapidly:

- Creating a Cloud Storage bucket, uploading a fixture, reading it, and deleting the bucket completes in **`~16 ms`** total.
- Creating a Cloud SQL table, inserting 100 rows, running an aggregate query, and dropping the table completes in **`~11 ms`** total.
- Publishing and consuming 100 Pub/Sub messages completes in **`~16 ms`** total.

A suite of 100 end-to-end integration tests can finish in under **2 to 3 seconds**.

### Resource efficiency of the Lite image

The LocalCloud Lite runtime packages 22 emulators, the reverse proxy gateway, and PostgreSQL into one lightweight container image with approximately **`35 MB`** of runtime memory overhead at startup.

## How to reproduce

Execute the test suite with `uv` from the `localcloud-cli` repository:

```bash
# 1. Run complete benchmark suite:
uv run python scripts/perf_benchmark.py \
  --cli-path dist/localcloud \
  --data-volume localcloud-perf \
  --image agentcloud/localcloud:lite \
  --output-json perf_results.json \
  --output-markdown docs/performance-benchmarks.md

# 2. Run fast sanity verification:
uv run python scripts/perf_benchmark.py --quick
```
