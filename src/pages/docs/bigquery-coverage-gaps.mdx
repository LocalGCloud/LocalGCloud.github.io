# BigQuery coverage and known boundaries

LocalCloud's current source uses native GoogleSQL analysis and DuckDB execution. The [feature reference](/docs/bigquery-emulator-features/) covers LocalCloud endpoints and runtime operation boundaries.

This page summarizes the BigQuery emulator's versioned coverage matrix. The matrix includes canonical and derived records; its total is a count of records, not a count of distinct canonical GoogleSQL capabilities or executed tests.

<Callout type="warning" title="Recorded source coverage">
These counts are the dependency's recorded classifications. Test the features your application depends on with the LocalCloud image you run. Unknown records are unassessed. Unsupported records include local feature gaps as well as managed-cloud behavior.
</Callout>

## Unsupported and unknown records

Before relying on a capability that this page does not list, test it with your application's queries. Unsupported and unknown states must not be reduced to cloud scale alone: syntax, model variants, external sources, collation, and individual API methods can have developer-visible gaps. A successful dry run, stored configuration, or metadata operation does not prove execution support.

## How to check a capability

1. Check the required capability ID and its exact operation and input boundary.
2. Confirm the dependency identity used by the LocalCloud image; dependency HEAD can differ from a packaged payload.
3. Run the application's query or API workflow, assert the result and errors, and test restart when persistent state matters.
4. Record client versions, platform, dependency revision, assembled-image digest, failures, and skips.
5. Validate required production behavior against Google Cloud using a separate environment.
