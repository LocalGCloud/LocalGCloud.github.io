# Seed data

LocalCloud accepts YAML fixture data at root operator endpoints. It is not a migration, backup or production-data tool.

## Load and reload

```bash
curl -fsS -X POST http://localhost:5380/seed \
  -H 'Content-Type: application/yaml' \
  --data-binary @seed.yaml
```

The canonical gateway URL applies to manual Docker. With the host CLI, derive the actual gateway URL from `localcloud start`, `localcloud status`, or `localcloud env` because port `5380` can be remapped.

Other routes:

| Route | Behavior |
| --- | --- |
| `POST /seed` | Load a YAML body. |
| `POST /import` | Alias of `/seed`. |
| `POST /reseed` | Reload `LOCALCLOUD_SEED_FILE`, default `/opt/localcloud/seed.yaml`; replace default sample resources in the selected project, including changes inside them. |
| `POST /reset?project=...` | Clear one project; `{"restore_seed":true}` reapplies that project's most recently loaded seed when available. |

## Accepted envelopes

### Flat service keys

```yaml
gcs:
  buckets:
    - name: localcloud-docs-bucket
      objects:
        - key: fixtures/hello.txt
          content: Hello from LocalCloud

pubsub:
  topics:
    - name: docs-events
      subscriptions:
        - name: docs-events-sub
```

### One-project `services` mapping

```yaml
services:
  gcs:
    buckets:
      - name: localcloud-docs-bucket
  secretmanager:
    secrets:
      - name: docs-api-key
        versions:
          - data: fake-local-value
  bigquery:
    datasets:
      - name: analytics
        location: US
    tables:
      - dataset: analytics
        name: events
        schema:
          fields:
            - name: event_id
              type: STRING
              mode: REQUIRED
        rows:
          - event_id: event-001
```

BigQuery tables are top-level entries under `bigquery.tables`; every table names its dataset. Secret Manager records belong under `secretmanager.secrets`.

### Multi-project mapping

```yaml
projects:
  local-gcp-project:
    services:
      gcs:
        buckets:
          - name: localcloud-main-project
  second-local-project:
    services:
      pubsub:
        topics:
          - name: second-project-events
```

## Services that accept seed data

Seed data loads into: `gcs`, `pubsub`, `bigquery`, `spanner`, `secretmanager`, `cloudtasks`, `memorystore`, `workflows`, `cloudscheduler` (alias `scheduler`), `cloudfunctions` (alias `functions`), `alloydb`, `dataproc`, `cloudiam` (alias `iam`), `cloudsql`, `bigtable`, `sheets`, `firestore` and `kms`. A service must be enabled before its seed data loads.

`firestore` is disabled by default. Enable it explicitly before seeding it, and check its operation limits. A successful import doesn't prove a service's full query, listener or recovery behavior. Test those with your application.

## Startup file

Sample data loads automatically on first start. Set `server.auto_seed: false` to turn it off. The CLI doesn't mount or apply seed files, and `host.seed` is ignored. For manual Docker, mount your seed file together with the data volume:

```bash
docker volume create localcloud-data

docker run -d --name localcloud \
  -p 127.0.0.1:5380-5405:5380-5405 \
  -m 4g \
  -v "$PWD/seed.yaml:/opt/localcloud/seed.yaml:ro" \
  -v localcloud-data:/var/lib/localcloud \
  agentcloud/localcloud:latest
```

Prefer `localcloud start`. For repeatable runs, pin an image digest.

## Terraform interaction

`LOCALCLOUD_TERRAFORM_MODE=true` causes seed requests to return a skipped result so Terraform-managed resources are not duplicated. Do not combine a Terraform resource-creation test with implicit startup seed data.

## Fixture safety

- Use stable IDs, deterministic values, and small datasets.
- Use fake secret payloads only; never copy production credentials or customer data.
- Assert the data through the same SDK/API path the application uses.
- Reset only the intended project and verify the response before continuing.
- Validate production migrations, backup and recovery, and secret handling in Google Cloud.
