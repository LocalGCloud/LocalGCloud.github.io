# BigQuery feature comparison: historical analysis

<Callout type="warning" title="Archived as of 2026-04-20">
This document compared an earlier Python/SQLGlot/DuckDB rewrite with another emulator while implementation was still being planned. It is retained as design history. Its `Y`, `P`, `N`, planned-phase, function-count, view-count, and syntax statements are **not current LocalCloud compatibility claims**.
</Callout>

## Why this page is archived

The current BigQuery dependency has changed materially since this analysis. Features described here as absent or planned—including bounded scripting, materialized-view emulation, external-data paths, Storage API profiles, broader `INFORMATION_SCHEMA`, grouping extensions, `TABLESAMPLE`, and search/vector behavior—now have newer source or test evidence.

LocalCloud still lacks a pinned, qualified dependency image and assembled-image digest. That means the old analysis cannot simply be inverted into a current support matrix either.

## Historical value

This analysis remains useful for understanding design risks that still matter:

- a parser accepting syntax does not prove correct execution;
- DuckDB and BigQuery can differ in coercion, errors, numeric behavior, geography, and distributed semantics;
- metadata-only or empty compatibility surfaces are not production behavior;
- infrastructure systems such as reservations, billing, quotas, IAM, and audit logging require separate treatment.

Do not use this page to approve a feature, client, language SDK, or release. Use an immutable dependency revision, assembled image digest, qualification result, and durable evidence record instead.
