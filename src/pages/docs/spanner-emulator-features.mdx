# Spanner emulator feature reference

LocalCloud integrates an extended Cloud Spanner emulator. GoogleSQL and PostgreSQL dialects run through the Spanner API; dialect support does not imply complete SQL, transaction, graph, search, authorization, backup, or change-stream parity.

<Callout type="warning" title="Use the operation boundaries">
The table below retains the runtime's recorded operation boundaries and limitations. Standalone dependency tests don't cover the LocalCloud image. Validate the exact client, operation, dialect, and image used by the application.
</Callout>

## Connections and persistence

| Surface | Canonical value | Boundary |
| --- | --- | --- |
| gRPC API | `SPANNER_EMULATOR_HOST=localhost:5386` | Use generated host ports and test the selected SDK/version. |
| REST gateway | `http://localhost:5387` | REST / grpc-gateway, not PostgreSQL wire. |
| PostgreSQL dialect | Queries through the Spanner API | LocalCloud does not package PGAdapter; `psql` and pgJDBC need a separately configured adapter. |
| State | LevelDB rows and JSON metadata under `/var/lib/localcloud/spanner-data` | Mounted storage is required for retained state; see the recovery limits below. |

Use `localcloud env` for the actual mapped endpoints. Provision the instance, database, and schema before querying; a code example that refers to an uncreated database is not a complete quick start.

## Exercise a transactional workflow

1. Follow the [Python SDK example](/docs/sdk-examples/#spanner-python) to create an instance, database, and schema before opening the application client.
2. Insert a small order and inventory fixture. Update both in one transaction and query the committed values.
3. Run conflicting updates with the isolation level your application selects. Assert wound-wait conflict handling, retries, and the final inventory value.
4. If the application uses database roles, create a session with `creator_role` and check both allowed and denied operations.

## Follow committed changes

1. Create a change stream for the fixture table and read it through `ExecuteStreamingSql`; unary `ExecuteSql` does not read change streams.
2. Commit a write while the reader is active. Check the data-change record, transaction metadata, and heartbeat handling.
3. Resume at the stream's row-boundary token and assert the consumer's handling of repeated records. Use persistent storage when testing retained stream state across restart.

## Runtime and recovery limits

Backups and durable stream recovery require the mounted Spanner data directory. Back up known rows, restore into a separate database, and compare schema and data. A successful backup operation alone does not validate recovery.

Unauthenticated emulator connections bypass network IAM. Database-role checks do not establish Google IAM authority; CMEK and Google-managed regional behavior require cloud validation.

Verify production IAM, managed replication, regional availability, performance, and required functional behavior in Google Cloud before release.
