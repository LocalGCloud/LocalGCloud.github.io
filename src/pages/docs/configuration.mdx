# Configuration

LocalCloud reads runtime configuration from environment variables. The host CLI is the recommended operator interface because it binds ports to loopback, can remap occupied ports, and returns the actual endpoints for the selected instance.

```bash
localcloud start
eval "$(localcloud env)"
```

`localcloud.yaml` is a **host CLI** configuration file discovered in the current directory; CLI flags override it. The runtime file `application.yaml` is reference material only and is not automatically loaded by `LocalCloudConfig`.

## Core settings

| Variable | Runtime default | Purpose |
| --- | --- | --- |
| `LOCALCLOUD_PROJECT` | `local-gcp-project` | Default project when a request does not select one explicitly. |
| `LOCALCLOUD_DATA_DIR` | `/var/lib/localcloud` | Persistent runtime data root. |
| `LOCALCLOUD_PERSISTENCE` | `true` | Enables supported persistent stores. Service-specific behavior still varies. |
| `LOCALCLOUD_SERVICES` | Registry defaults | Complete comma-separated service-set override. |
| `LOCALCLOUD_SEED_FILE` | `/etc/localcloud/seed.yaml` | File used by `/reseed` and startup seeding. |
| `LOCALCLOUD_IAM_MODE` | `permissive` | `permissive`, `strict`, or `gcp-live`. |
| `LOCALCLOUD_IAM_POLICY_FILE` | empty | Local identity-to-path policy JSON used by strict mode and optionally by `gcp-live`. |
| `LOCALCLOUD_TELEMETRY` | `true` | Runtime telemetry preference; see [Privacy](/docs/privacy/) for the verified limitations. |

To choose another project, start the instance with `LOCALCLOUD_PROJECT`, use the CLI project option/configuration, or request `/env?project=my-project`. Keep examples and tests explicit when their project differs from `local-gcp-project`.

## Service selection and precedence

Service configuration follows this order:

1. If `LOCALCLOUD_SERVICES` is set, it is the complete enabled set. Individual `LOCALCLOUD_ENABLE_<SERVICEID>` flags do not override it.
2. Otherwise, `services.yaml` registry defaults apply.
3. Individual `LOCALCLOUD_ENABLE_<SERVICEID>=true|false` values override those defaults.
4. Persisted console configuration applies only where an environment value has not locked that service.

## IAM modes

- **`permissive`** (default): non-administrative requests are accepted without credential checks. This is convenient, not a production security boundary.
- **`strict`**: a bearer identity is matched against path prefixes loaded from `LOCALCLOUD_IAM_POLICY_FILE`. Without a policy, non-exempt requests are denied. Administrative and developer paths such as `/health`, `/services`, `/env`, `/seed`, `/reset`, and console assets remain exempt.
- **`gcp-live`**: bearer tokens are validated with Google OAuth tokeninfo, creating outbound network traffic. If a local policy is loaded, it is also applied. The runtime does not currently call its declared `testIamPermissions` URL, so this is not production IAM parity.

Never describe strict or `gcp-live` mode as equivalent to Google Cloud IAM enforcement. See [Privacy](/docs/privacy/) before enabling behavior that contacts external services.

## Operator endpoints

All operator routes are rooted at the gateway; the retired underscore-prefixed namespace is not part of the API.

| Route | Purpose |
| --- | --- |
| `/health` and `/health/{service}` | Health summaries. |
| `/readiness` | General runtime readiness. |
| `/services` | Service state and metadata. |
| `/env` | Shell, JSON, Terraform, or Docker Compose environment output. |
| `/seed`, `/reseed`, `/import` | Seed/import operations. |
| `/reset` | Project-scoped reset. |
| `/terraform/readiness` | Terraform routing and certificate readiness. |
| `/graphql`, `/api-docs`, `/docs` | GraphQL and API discovery surfaces. |

## SDK environment

Use generated values rather than copying canonical ports. The CLI can dynamically remap occupied host ports.

```bash
eval "$(localcloud env)"
```

For a manual Docker runtime on canonical ports:

```bash
eval "$(curl -fsS 'http://localhost:24080/env?format=shell')"
```

The output includes enabled-service endpoint variables plus project and caller values. Scope them to the shell or process running local tests. Stop if a client attempts real Google Cloud rather than adding production credentials.

## Manual Docker Compose fallback

Prefer the CLI. On unsupported CLI hosts, this loopback-bound fallback publishes canonical ports without mounting the Docker socket:

```yaml
services:
  localcloud:
    image: jaysen2apache/localcloud:latest
    ports:
      - "127.0.0.1:24080-24092:24080-24092"
    environment:
      LOCALCLOUD_PROJECT: local-gcp-project
    volumes:
      - localcloud-data:/var/lib/localcloud
    deploy:
      resources:
        limits:
          memory: 4g

volumes:
  localcloud-data:
```

The mutable image tag has not been tied to a qualified assembled-image digest. Pin a qualified digest for release workflows. Docker-socket and transparent-network access are opt-in and have separate security implications.
